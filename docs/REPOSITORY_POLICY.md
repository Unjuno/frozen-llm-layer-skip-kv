# Repository Policy｜公開研究ノートの運用規約

> **目的：** 研究の設計・方法・判断を追跡できる公開メモ。コードや性能が完成したと見せるためのリポジトリではない。

## 基本仕様を守る優先順位

**研究の中心は[01 研究の骨格](01_FOUNDATIONS.md)と[11 第1Attention活性の共有・Linear Head](11_SHARED_ACTIVATION_ROUTING.md)。** 最初から指定されている「第1Attentionの活性を再利用し、Linear Headでトークン別の全中間層実行領域を学習する」設計を、KV補完負債・GPU費用・経路維持などの派生案で上書きしない。

- **設計仕様・未決事項を区別**し、Tap位置や追加の損失項を助手が勝手に確定しない。
- **KV Cache関連の数理文書（06/08/09）や新規性監査（10）は補助資料**として維持し、研究目的の正本は01/11とする。
- **実装・学習・実験・研究日誌はユーザーから別の依頼があるまで新規作成しない**。
- 主設計との矛盾が見つかった場合は、[設計判断ログ](DECISIONS.md)に訂正理由を追記し、GitHubの最新文書を整合させる。

## 変更方法：原則`main`へ直接コミット

1. 原則は**`main`で直接作業し、直接コミット**。通常の研究メモの更新にPR・マージ用ブランチを要求しない。
2. 1コミットで何を変えたか分かるよう、関連する変更を小さくまとめる。
3. **履歴改変のforce-pushは避ける**。変更理由は[設計判断ログ](DECISIONS.md)へ追記する。
4. 複数人による同時作業が必要になった場合だけ、Branch/PR運用を再検討し、規約を明示的に更新する。

## 何をどこへ書くか

| 変更内容 | 更新先 |
|---|---|
| 研究目的・凍結範囲・Router配置を変更 | [01](01_FOUNDATIONS.md) ＋ [判断ログ](DECISIONS.md) |
| サンプリング、報酬、勾配を変更 | [02](02_ROUTER_TRAINING.md) ＋ [判断ログ](DECISIONS.md) |
| 保存・KV補完の方式を変更 | [03](03_KV_CACHE.md) ＋ [判断ログ](DECISIONS.md) |
| Baseline・品質閾値・測定方法を変更 | [04](04_EVALUATION.md) ＋ [判断ログ](DECISIONS.md) |
| 実装・検証の進捗・失敗を記録 | [05](05_GATES.md) |
| トップページの概要やリンクを直す | [README](../README.md) ＋ [文書ガイド](README.md) |

**研究結果を追加するときは**、GPU型番・Clock・メモリ、Model revision、Backend、精度、Batch、入力/出力長、Seed、データ版、反復回数、統計手法を併記する。未測定の速度改善・精度向上を既成事実として書かない。

## 変更を記録する最低限の情報

- 何を変えたか（変更前・変更後）。
- なぜ変えるか（数理的根拠、一次文献、測定値、実装制約）。
- どの比較実験・正確性条件に影響するか。
- 確定／提案／保留／未検証／検証済みのどの状態か。
- 比較可能性が失われる場合、どの条件を測り直すか。

## 公開・安全とライセンス

- 秘密鍵、アクセストークン、機密データ、非公開プロンプトをコミットしない。
- 第三者のモデル重み・データセット・コードは独自の利用規約に従う。MITはその利用許諾を代替しない。
- 巨大なモデル重み・KVダンプをGit履歴へ直接追加しない。
- 再現可能性と否定的結果の記録を優先し、誤解を招く「達成済み」表現を避ける。

## 段階管理

**研究には週単位の期限を置かない。** [G0〜G8](05_GATES.md)で合否と次の検証を記録する。研究ノートの文書化完了と、研究仮説の成立は別の状態である。
