# Research Protocol — Frozen-LLM Layer Skipping × Deferred KV Reconstruction

> **Status: proposed research protocol / 計画段階。** これは実装・測定結果ではない。実験期限は設定しない。確定仕様・仮説・未確定事項を混同しない。

## 0. 研究課題と非目標

**中心課題：** 全重みを凍結したLLMの第1層出力から、中間層すべてのON/OFFをトークン単位で一括選択するLinear Routerを**実際の生成報酬で学習**し、スキップによる品質維持／改善とGPU高速化を実証できるか。さらに、スキップ層の欠損KVについて遅延・一括補完を可能にし、**経路選択と補完費用の共同最適化**が単純結合を上回るかを検証する。

固定仕様：

- 対象は **Qwen3-0.6B → Nanbeige4.3-33B** の2段階。中間3B/7Bモデルなし。
- Embedding、全Transformer層、LM Headの重みは凍結する。学習可能なモデルパラメータは**Linear Routerのみ**。
- 最初と最後のTransformer層を必ず実行。中間すべての層はON/OFF候補。
- 第1層後の隠れ状態から、現在トークン用の**全中間層マスクを1回で出力**する。中間層ごとに順番にRouterを呼ぶ設計とは異なる。
- 初期仕様では**Prefillは全層実行、Decodeのみ動的スキップ**。
- 訓練中に複数プロンプトで多様なマスク経路を実際にRolloutし、全軌跡のタスク報酬と費用でRouterを更新する。
- **元モデルへの出力一致だけを主報酬にしない**。元モデルの誤答を正せる可能性も検証する。
- 実行層数・FLOPsは補助指標であり、品質制約を満たす**実GPU Decode遅延**を主指標とする。

非目標：既存モデル重みのファインチューニング、事前学習のやり直し、モデル間Router重みの直接転用、最初から高度なCUDA実装に着手すること、結果未測定の高速化宣言。

## 1. 研究仮説

| ID | 反証可能な主張 | 主要な比較 |
|---|---|---|
| H1 | 学習したLinear Routerが、同等の平均実行層数の固定スキップより良い品質・費用トレードオフを示す | 固定マスク vs 学習済みRouter |
| H2 | 同じマスク列・トークン列なら、遅延／一括／適応的KV補完はEagerに対して遅延またはメモリの利益を示す | Eager vs Lazy / Batched / Adaptive |
| H3 | **KV補完費用を考慮したRouterの再学習**が、Schedulerの単純後付けより有利となる | 単純結合 vs 共同最適化 |
| H4 | 元モデルより高品質な経路が存在し、学習済みRouterが未見問題で正解率の改善を再現できる | 全層モデル vs 学習済みRouter |

H4の「探索中により良い経路が見つかった」と「学習Routerが未知問題で一度に選べた」は**別の結論**として扱う。

### 2.3 Linear Routerとマスクサンプリング

全中間層の確率を**一回のLinear Head**で出す。

\`\`\`math
p_t=\sigma(Wh_t+b)
\`\`\`

学習時はRouter出力に探索用の独立ビット反転を加える。反転前確率と反転後のサンプリング確率は異なる。

\`\`\`math
q_{t,j}=\varepsilon+(1-2\varepsilon)p_{t,j},\qquad
m_{t,j}\sim\mathrm{Bernoulli}(q_{t,j})
\`\`\`

初期方式では、現在の特徴量に条件付けたBernoulli積で**マスク全体**をサンプリングする。

\`\`\`math
\pi_\theta(m_t\mid h_t)=
\prod_{j=2}^{L-1}
q_{t,j}^{m_{t,j}}(1-q_{t,j})^{1-m_{t,j}}
\`\`\`

ここでの条件付き独立性は、**層間相関を完全に表現できることを保証しない**。ただし報酬は組み合わせ全体に与えるため、各層のON/OFFを単独に採点するわけではない。

**次元チェック：** Wh+bは(L−2)次元の無次元スコア。確率・マスク・その積はいずれも無次元で整合。

### 2.4 報酬と方策勾配

主報酬はタスク正解性と費用の組合せ。元の教師モデルとのKL距離だけにはしない。

\`\`\`math
R(\tau)=Q(\tau)-\lambda\,T(\tau)/T_0
\`\`\`

学習初期のTは実行層数などの代理費用を時間相当に換算した推定値でもよいが、**実測値との区別を必ずログに残す**。最終評価では実GPU時間を測る。品質の非劣性は報酬と別の制約として評価する。

\`\`\`math
J(\theta)=\mathbb{E}_{x,\tau}[R(\tau)]
\`\`\`

\`\`\`math
\nabla_\theta J=
\mathbb{E}_{x,\tau}\left[
(R(\tau)-b_{LOO})
\sum_t\nabla_\theta\log\pi_\theta(m_t\mid h_t)
\right]
\`\`\`

**導出の要点：** 凍結LLMとマスク・トークン列を固定したとき、Routerパラメータは選択したマスクの確率に現れる。軌跡確率の勾配を「軌跡確率×対数確率の勾配」に展開するとREINFORCEを得る。更新時のRouterを固定した条件で、独立な別Rolloutから作るLeave-one-out基準値は対象Rolloutの選択に依存しないため、期待勾配を変えない。

**単位チェック：** T/T_0 は s/s で無次元、Qとλも無次元。報酬と対数確率も無次元。

**ERROR CHECK：** 学習時は実際にサンプリングしたqの対数確率を使う。pの確率を使うと、意図した方策勾配の不偏推定にはならない。Schedulerがマスクを上書きする場合、その変換を含む確率・実行経路を扱う必要がある。上式は低分散・収束速度・品質改善を保証しない。

## 3. Online学習プロトコル

1. 学習用プロンプトを抽出。同一プロンプトについて**4〜8本をPilot候補**として独立にRolloutする（本学習規模はPilotで再設計）。
2. 第1層後の特徴からマスク全体をサンプリングし、必須第1層・最終層を残して実際に生成する。
3. 記録：プロンプトID、モデルrevision、生成トークン列、各位置のマスク・log probability・スキップ数・報酬・GPU費用。
4. 凍結LLM側はgradientを保持せず、Routerの学習用にはdetachした第1層特徴とマスクを保存し、更新時にRouter対数確率を再計算してよい。
5. 機械的に検証できるタスク正解性を主報酬にし、生成長・フォーマット異常・早期停止を別監視する。
6. Leave-one-out型ベースラインでRouterを更新。比較：未学習ランダム／単純REINFORCE／Leave-one-out／少数スキップからのCurriculum。
7. 学習曲線と未見検証データを用いて方策崩壊（常時全ON、常時全OFF、反復生成など）を監視する。
8. 小型MLPをLinearの**対照実験**として追加してもよいが、主方式はLinearのまま。

**決定的な切り分け：** 「同じプロンプトで探索すれば正解経路が存在する」ことと、「Routerが一発で未知問題の経路を選べる」ことは別。Search Oracleの数値を実運用性能として報告しない。

## 4. KV補完プロトコル

### 4.1 同一経路での参照意味論

- **Eager：** ブロックをSkipしても、当該層**への実際の入力**からK/Vを生成・保存する。Attention/MLP出力は適用しない。
- **On-demand：** 層入力と位置を保存し、その層が後で実行される前に、必要な過去位置のKVを復元する。
- **Batched：** 複数欠損位置のK/V射影をまとめ、元の位置・順序・RoPEを保持する。
- **Shared Lazy：** 完全スキップにより同じ隠れ状態が伝播する連続区間で、保存する層入力を共有する。**異なる層の射影重みは共有しない**。
- **Adaptive：** VRAM予算・GPU実行費用・補完期限に応じ、Eager／Lazyを使い分ける。

### 4.2 正確性の不変条件

1. ある層のAttentionを実行する時点で、参照する全過去位置のKVが揃っている。
2. 保存状態は**当該スキップ経路での層入力**。全層実行モデルの別の隠れ状態で代用しない。
3. Position ID・RoPE・K正規化・Attention Mask・KVレイアウトは対象モデルと一致する。
4. 連続スキップの状態共有は、Skipがそのブロックの完全な恒等写像である場合のみ成立。
5. 保存入力は未完了の補完が残る限り解放しない。メモリ逼迫による無条件破棄は許さない。
6. 非同期CUDA Streamでも、必要なKVを書き終えるEventより前にAttentionを開始しない。
7. BF16の異なるKernelによる丸め誤差は「厳密な実数演算上の同値性」と区別する。

### 4.3 連続スキップ入力共有の容量上限の目安

\`\`\`math
M_{state}=ds,\qquad
M_{KV}=2k\,n_{KV}\,d_hs
\`\`\`

共有隠れ状態の方がEager KVより**単純保存容量で**小さくなる条件：

\`\`\`math
k>\frac{d}{2n_{KV}d_h}
\`\`\`

BF16、モデルconfigの数値を使用するとQwen3は**連続1層以上**、Nanbeigeは**連続4層以上**が目安。なお、この式は1 token×1区間の状態とKVだけを比較し、Allocatorや後から生成されるKVの共存、参照管理、実行時間を含まない。**小さい方が速いとは限らない**。

**次元チェック：** 保存容量は無次元の要素数×B/要素＝B。容量の大小を決める閾値は無次元。

### 4.4 KV検証セット

- native full model vs **masked all-ON** のLogits・生成比較。
- 固定マスク・固定生成トークン列のReplayで Eager vs On-demand vs Batched vs Shared/Adaptive のKV・Logits比較。
- マスク：単層Skip、連続Skip、交互Skip、すべての中間層Skip、長期間のSkip後の再実行。
- キャッシュ状態：\`KV_READY\` / \`INPUT_SAVED\` / \`UNAVAILABLE\` を追跡。
- 正しい位置と値、欠損参照・NaNの不在、ピークVRAM、CUDA Event依存関係の遵守。
- 異なる計算Kernelの許容誤差は**実験前に**定義し、bitwise一致と近似一致を区別する。

## 5. GPU測定・共同最適化

### 5.1 Backendの役割

- 正確性実装：Hugging Face Transformers＋PyTorch。モデルrevision・Tokenizer・Attention Backendを固定。
- 速度実装：CUDA対応実行器を別途設計・比較（SGLang系実装も検討）。\`.item()\`等のCPU同期、Gather/Scatter、Kernel Launch費用が重要。
- **FLOPs削減率は実測速度の代用にしない**。Batch 8では少数トークンの層実行によって重みアクセスが残る可能性がある。

### 5.2 GPU費用モデル

Microbenchmarkで実測する要素：実行層集合、Batch、Context長、KV補完数、補完待ち量、Eager/Lazy選択、Router、トークンGather/Scatter、待機・同期。計測にはCUDA EventsとNsightを使い、Kernelの非同期実行・重なりを考慮する。

- **D1 単純結合：** Eagerで学習したRouterを固定し、Schedulerを追加。
- **D2 共同最適化：** 同じSchedulerの下で補完費用込みの報酬によりRouterを再学習。
- D1とD2は学習データ・評価セット・Backend・品質閾値を可能な限り揃え、再学習に投入した追加費用も報告する。

最終的な性能比較は**必ず実GPU生成時間**とする。学習時の推定費用の適合度も測定する。

## 7. 評価と再現性

### 7.1 データ

- 訓練／開発・Pilot／最終テストを明確に分離し、リーク・重複問題を検査。
- Pilot 128〜256プロンプトは開始値であり、学習本数・最終テスト本数は**Pilotから検出力を推定して決める**。
- 学習Seedは少なくとも3個。評価データと学習条件をTestの結果から恣意的に変更しない。
- 正解判定可能な選択式・数学・コード等を優先。正解率、早期EOS、生成長、形式遵守を別に記録。

### 7.2 GPU条件

- 初期測定候補：BF16、Batch 1/8、Prefill長128/1024 token、固定Decode長128/512 token。
- GPU型番・メモリ、Driver/CUDA、Clock/電力、PyTorch/Transformers、実行Backend、精度、Seed、モデルrevision、Tokenizer/Chat Templateを記録。
- Warm-up後に反復測定。計測順を交互／ランダム化し、中央値・p95・対応付き信頼区間を報告。
- 出力長固定のDecode時間と、自然EOSまでのEnd-to-end時間を**別々に**集計。
- 学習用の推定時間と、後から測った実測時間は明確に分ける。

### 7.3 H / T / D / C / U

| 項目 | 事前登録の考え方 |
|---|---|
| H | H1〜H4を別々に検証。最終的な目標は品質非劣性を満たした実GPU Decode時間の短縮。 |
| T | 独立テスト、最低3学習Seed、対応付き速度測定。Pilotで評価数と停止条件を定め、Test前に固定。 |
| D | 暫定目標：品質非劣性を満たし、速度改善の点推定5%以上・95%CI下限>0。強いPASS：下限>5%。不整合や品質悪化はFAIL。精度不足はUNCERTAIN。 |
| C | 探索の分散、Linearの情報不足、方策崩壊、KV同期・GPU帯域、メモリ圧迫、未見タスクへの一般化失敗。 |
| U | プロンプト分布、学習Seed、生成乱数、Clock・電力・Backend。階層性と対応関係を保った区間推定。 |

品質非劣性の**暫定例**はNLL増分0.02 nat/tokenと正解率低下2パーセントポイント。Test前に根拠とともに確定する。品質改善は元モデルの「誤→正」「正→誤」を対応付きで集計し、必要に応じてMcNemar検定またはBootstrapを使う。

- Linear Headが第1層の特徴だけで十分に経路を選択できるか。

- 既存研究との新規性境界。先行研究の整理は別途根拠付きで更新する。
