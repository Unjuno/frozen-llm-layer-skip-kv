# 02｜Linear Routerの生成中学習

> **状態：** 手法案。Linear Routerのみを学習することは確定。REINFORCE、基準化、探索率や報酬係数は**初期実装候補**であり、性能は未検証。

## 何を学習するか（最重要）

**入力：** 現在のDecodeトークンについて、第1 Transformer層を実行した後の隠れ状態。

**出力：** 中間Transformer層**全部**の実行確率（Qwen3: 26、Nanbeige: 50）。

**選択：** 中間層ごとに0/1を持つマスクを**一括サンプリング**。最初・最後の層は常にON。

**報酬：** 選択した全マスク列で**実際に文章生成した結果**の品質・推論費用から計算。単一の「スキップする層」を教師として選ばない。

**学習：** 凍結LLMに勾配を通さず、**Linear Routerのパラメータだけ**更新する。

### 実装する学習ループ（設計）

1. 学習プロンプトを1つ取り、**同じRouterパラメータ**で4〜8本を初期候補として独立にRolloutする。
2. 各トークンの第1層出力から26/50個の確率を一括算出する。
3. 確率と探索ノイズで中間層のON/OFFマスクを一括サンプリングし、各層を実行／スキップして次トークンを生成する。
4. マスク、log probability、生成トークン、生成長、費用、正解性、停止理由を記録する。
5. 各Rollout全体の**タスク品質と推定費用**から報酬を得る。同じプロンプトの他のRolloutを報酬ベースラインにする。
6. Routerの確率の対数から**Routerだけを更新**する。学習後、未知のValidationプロンプトで生成し直して検証する。

「ランダムにマスクを切り替えた」だけでは学習にはならない。生成報酬をRouterの選択確率へ結び付ける推定量を実装する必要がある。

## マスクの確率分布

```math
p_t=\sigma(Wh_t+b),\qquad
q_{t,j}=\varepsilon+(1-2\varepsilon)p_{t,j}
```

```math
m_{t,j}\sim \operatorname{Bernoulli}(q_{t,j}),\qquad
\pi_\theta(m_t\mid h_t)=\prod_{j=2}^{L-1}q_{t,j}^{m_{t,j}}(1-q_{t,j})^{1-m_{t,j}}
```

**条件付き独立Bernoulliは方策のパラメータ化の仮定**であり、層間相互作用がないという主張ではない。生成結果の報酬は組み合わせ全体に与える。ただし表現可能なマスク間相関は制限され、Linearの性能上限を別実験で検査する。

ビット反転を使うなら、**実際のqで対数確率を計算する**。pで更新すると意図した方策の正しい勾配推定にならない。

## 報酬と勾配

初期案（係数・費用モデルは未決）：

```math
R(\tau)=Q(\tau)-\lambda\frac{\widehat T(\tau)}{T_0},
\qquad
J(\theta)=\mathbb E_{x,\tau\sim P_\theta}[R(\tau)]
```

主品質報酬にタスクの正解性を使い、元の全層モデルとのKL距離は任意の補助比較に留める。元モデルの誤答を修正した経路を低く評価してはいけない。品質非劣性は報酬とは別に評価する。

### REINFORCEを使う数学的根拠

凍結モデルと固定された生成軌跡の下では、各位置のLLMの出力分布はRouter重みに直接依存せず、マスク選択の確率がRouter重みに依存する。

```math
P_\theta(\tau\mid x)=\prod_t \pi_\theta(m_t\mid h_t)\,P_{\rm LLM}(y_t\mid x,y_{<t},m_{\le t})
```

離散分布に対する微分を展開する：

```math
\nabla_\theta J
= \sum_\tau R(\tau)\nabla_\theta P_\theta(\tau\mid x)
= \sum_\tau P_\theta(\tau\mid x)R(\tau)\nabla_\theta\log P_\theta(\tau\mid x)
```

凍結LLMの項の直接微分はゼロなので、

```math
\nabla_\theta J
=\mathbb E\!\left[R(\tau)\sum_t\nabla_\theta\log\pi_\theta(m_t\mid h_t)\right]
```

基準値を対象Rolloutから独立に作れば、その勾配の期待値がゼロとなるため、

```math
\nabla_\theta J
=\mathbb E\!\left[(R(\tau)-b_{\rm LOO})\sum_t\nabla_\theta\log\pi_\theta(m_t\mid h_t)\right]
```

とも書ける。同じプロンプトの他Rolloutを**同じ固定方策から独立に**生成することが基準値の不偏性の重要条件。1グループの途中でRouter重みを更新しない。

**単位チェック：** 行列×ベクトルは無次元スコア、確率は無次元。時間比はs/sで無次元。したがって報酬と対数確率は無次元で、式の次元が整合する。

**ERROR CHECK：** これは不偏な勾配推定の条件であり、**低分散・効率的収束の証明ではない**。Router入力特徴を再計算するとき、凍結LLMの過去の生成状態を勝手に変更してはいけない。方策に依存したマスク後処理があれば、実際のマスク分布を正しく評価する必要がある。

## 実装の初期比較（すべて仮設定）

| 試行 | 設定 | 見たい効果 |
|---|---|---|
| 未学習Random | 同じON率のランダムマスク | 探索だけで得られる品質 |
| REINFORCE | 単純な全軌跡報酬 | 最小構成 |
| REINFORCE + LOO | 同一プロンプト複数Rollout | 分散低減 |
| + Curriculum | 初期ON率高め → 徐々にスキップ増加 | 学習崩壊対策 |
| + GPU Cost | 実測に較正した費用で再学習 | 共同最適化 |

例：初期ON確率0.95とすると、Qwen3のスキップ期待数は26×0.05=**1.3層／token**。これは学習用の初期値案であり、最適性の主張ではない。探索率と学習率もPilotで調整する。

**記録必須：** 使用した実行マスクとlog probability、学習Seed、プロンプトID、出力列、回答の正誤、報酬、推定または実測費用の区別、早期EOS、ルータ出力のEntropy、学習更新回数。
