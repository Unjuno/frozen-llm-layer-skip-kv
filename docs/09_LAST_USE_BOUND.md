# 09｜層の最終実行位置と「本当に不要になるKV」の理論境界

> **状態：補助的な数学的命題。** 主研究は**第1Attentionの活性を共有した単一Linear Headによるトークン別の全中間層マスク学習**（[01](01_FOUNDATIONS.md)、[11](11_SHARED_ACTIVATION_ROUTING.md)）。本書の末尾OFF長は生成後の**解析量**であり、同じ層を長くSkipするよう学習させる目的ではない。恒等式自体の新規性は主張せず、実装・実験は未実施。

## 1. なぜこの考察が必要か

**遅延KV補完は、すべてのSkip位置のKV射影を省けるわけではない。**

トークンごとに異なる実行マスクを使う場合、ある層を一度Skipしても、**後のトークンが同じ層をONにすると、その過去位置のKVが必要**になる。そのため、Lazy方式の速度上の利益を最低限、次の二つに分解する。

1. **Projection elimination（射影そのものを省略）**：生成が完了するまで一度も必要にならなかったSkip位置のKV射影を計算しない。
2. **Projection scheduling（射影するが実行方法を改善）**：後で必要となるKVをまとめて射影し、Kernel Launch、GEMM効率、非同期の重なりを改善する。

**前者は実行マスクの時間的な構造に制約される。** 後者はGPU Backendの費用に依存し、計算個数の削減と別に計測・評価する。

## 2. 成立範囲・仮定

- 一つの生成要求について、**Prefill全層実行**、Decodeの中間層のみON/OFFを許す。
- スキップはTransformerブロックの**完全な恒等バイパス**。第1・最終層は必ず実行。
- **標準的な全履歴Causal Attention**で、後の位置が当該層を実行するとき、そのAttentionから参照可能な全過去位置のK/Vが必要。
- 同一マスク・同一生成トークン・同一位置で、Eager Project-OnlyとLazyが**等しいAttentionの意味論**を満たす。
- 対象層の過去KVを近似で省略しない。Sliding Window、Local Attention、位置限定マスク、KVの量子化、非同値な近似は**この命題の範囲外**。
- **生成終了後に同一要求が継続されない**ことを仮定。セッションを保持して将来の入力で再開し得るなら、現在のEOSを「永遠に必要ない」境界とみなしてはいけない。
- 定理は**「要求されたKV値の集合と数」**の比較であり、最小GEMM呼出し数や最小GPU時間を主張しない。

## 4. 命題1：固定マスクに対する「必要KV数」の厳密な境界

各層jのDecode中で最後のON位置を定義する：

```math
r_j=\max\left(\{t\in\{1,\dots,N\}:m_{t,j}=1\}\cup\{0\}\right).
```

Eager Project-OnlyはSkipした**全位置**のKV組も生成するため、

```math
N^{\rm eager}_{j}=\sum_{t=1}^{N}(1-m_{t,j}).
```

Lazyでも、そのSkip位置より**後に一度でも同じ層をONにする場合**、標準的なCausal AttentionのためにKVが必要になる。したがって必要な位置の集合は、Skipした位置で最後のONより前にあるもの：

```math
N^{\rm needed}_{j}=\sum_{t=1}^{r_j}(1-m_{t,j}).
```

差を取ると、

```math
A_j=N^{\rm eager}_j-N^{\rm needed}_j
=\sum_{t=r_j+1}^{N}(1-m_{t,j})=N-r_j.
```

**証明：**

1. `r_j` はDecodeでの最後のON位置。定義から全位置 `t>r_j` では `m_{t,j}=0`。よって末尾の和は項数 `N-r_j` に一致する。
2. `t<r_j` かつ `m_{t,j}=0` であれば、位置 `r_j` が層jをONにしてAttentionを実行する。このAttentionは全過去位置を参照するため、位置tの正確なKVが必要である。
3. 逆に `t>r_j` なら、その生成要求中には層jをONにする後続位置が存在しない。完了後の再開もないという仮定の下では、位置tのKVは後続の層j Attentionから参照されない。
4. よって、Skip位置のKVのうち、最終的に必須なのは `t<r_j` のものに一致し、不要なものはちょうど末尾の `N-r_j` 組である。

**証明終。**

**ERROR CHECK：** この命題は*同一マスク列を維持した正確なKV意味論*での必要値数に限る。局所Attentionが過去位置を参照しない、要求が後で再開される、マスクを後から変更する、そもそも当該KVが既に別の適法な方法で利用可能である場合、結論をそのまま使えない。数値演算の同一性と「KVが必要か」は別の問題。

**次元チェック：** 結果の各項はトークン個数で無次元。位置番号同士の差も無次元の個数。

### 実際に使う例：同じSkip数でも利益が違う

8位置のある**中間層1層**について、マスクを示す（1=ON、0=OFF）。

| 層のON/OFF（t=1〜8） | OFF位置数 | 最後のON位置 | Lazyなら完全に不要なKV組 |
|---|---:|---:|---:|
| `11110000` | 4 | 4 | **4** |
| `01010101` | 4 | 8 | **0** |

二つは**同じ実行層数・同じSkip率**でも、「後からKVを生成せずに済む位置数」は異なる。これは研究の費用関数を**平均Skip率だけで代表させてはならない**ことを意味する。

## 5. 命題2：IIDマスクなら永続的に省略できるKVは少なくなりやすい

**仮定：** ある層jについて、N個のマスクがON確率p、OFF確率q=1−pで独立同分布である。これは**説明用の確率モデル**で、現行Linear Routerが実際にIIDであるとは主張しない（実際のhは履歴依存）。

末尾連続OFF長ZのTail-sum formulaを使う：

```math
\mathbb E[Z_j]=\sum_{k=1}^{N}\Pr(Z_j\ge k).
```

末尾k個がすべてOFFである確率は `q^k` だから、

```math
\mathbb E[A_j]=\mathbb E[Z_j]=\sum_{k=1}^{N}q^k
=\frac{q(1-q^N)}{p}\quad(0<p\le 1).
```

p=0ならすべてOFFで `\mathbb E[A_j]=N`、p=1なら0。

**証明：** 非負整数Zについて `Z = Σ_{k=1}^N 1[Z≥k]` が各標本で成立する。両辺の期待値を取るとTail-sum formulaが得られ、IIDにより `Pr(Z≥k)=q^k`。有限等比級数を計算して右式となる。

**次元チェック：** 期待KV組数は無次元。pとqと指数Nは無次元で、式も無次元。

### 仮想的な数値例（GPU性能ではない）

| 生成長N | 1層のON確率p | 平均OFF数 | Lazyで完全に不要なKV（期待数） | 全OFFのうち不要になる割合 |
|---:|---:|---:|---:|---:|
| 128 | 0.5 | 64 | 約1.0 | 約1.56% |
| 128 | 0.1 | 115.2 | 約9.0 | 約7.81% |
| 512 | 0.1 | 460.8 | 約9.0 | 約1.95% |

**含意：** 独立にON/OFFを激しく切り替える方策では、ほとんどのSkip位置のKVが後で必要になり、**LazyがK/V射影の総回数を減らす効果は限定的**になり得る。性能上の利益があるなら、一括化・非同期化など**実行の方法**による場合もある。

**ERROR CHECK：** この表はGPU・Batch・Clock・補完時間の測定値ではない。マスク生成が履歴依存であればIID前提が破れ、期待数は変わる。品質が維持されるという保証はない。

## 6. 命題3：同じ平均ON率でも時間的相関が大きく影響する

時間的なON/OFFを二状態Markov連鎖（定常開始）と仮定し、OFF→ON確率をa、ON→OFF確率をbとする。

定常OFF確率は `q=b/(a+b)` で、末尾k個すべてがOFFの確率は `q(1-a)^{k-1}`。ゆえに

```math
\mathbb E[Z_j]=q\sum_{k=1}^{N}(1-a)^{k-1}
=q\frac{1-(1-a)^N}{a}.
```

**証明：** 定常分布から最後のk位置の最初がOFFとなる確率はq、その後k−1回連続でOFFを維持する確率はMarkov性から `(1-a)^{k-1}`。Tail-sum formulaと等比級数を適用する。

**次元チェック：** q、a、b、確率はすべて無次元。結果はトークン個数で無次元。

**仮想例：** N=128、定常ON率0.1、`a=0.02`、`b=0.18`なら、期待末尾OFF数は**約41.61**となる。同じON率0.1のIIDマスクの期待値**約9.0**とは大きく異なる。

**ERROR CHECK：** Markov性も定常分布も仮定。単に連続OFFを増やせば良いわけではない。OFFが長引くと隠れ状態の保存量と、途中でONに戻した際のKV補完バーストが増加し得る。品質上必要な層をOFFにし続ければ、タスク性能も悪化する可能性がある。

## 7. 構造を壊さず導入できる最適化の候補

### A：基準方式（確定した骨格）

第1層後のhからLinear Routerが中間層すべてのON/OFFを一括出力。学習は生成報酬、KVはEager基準。**変更しない**。

### B：同じLinear Routerで、**終端を含む総費用**を学習

学習時には、実際に発生するKV補完・待機・VRAM制約を含む**総Decode GPU時間**を報酬へ反映する。理論上の末尾OFF数は**分析・診断指標**に使うだけで、**追加の「省略KV報酬」として実際の時間報酬に二重加算しない**。

### C：KV状態を考慮した費用補正（任意、同一マスク維持を促進しない）

この節の**最終ON位置・末尾OFF長は生成完了後に確定する解析量**であり、推論時に未来の最後のONを知ることはできない。**OFFを長く継続させる学習報酬、前回マスクの一致ボーナス、強制的なON/OFFの固定化は採用しない**。

層の再利用による補完バーストや保存コストは、実際に発生するGPU時間として評価する。KV状態からの非学習の費用補正を比較する場合も、**入力に適応した層の選択を損なわないこと**を監査する。確定仕様の単一Linear Routerは変更しない。

**強い比較対象：** 開発データで選んだ、計算予算を揃えた最良固定マスク。これを上回らないなら、同じ層をずっとSkipする方策より動的Routerが有利とは主張しない。詳しくは[10 新規性の監査](10_NOVELTY_AND_RATIONALITY.md)。

### D：GPU側の一括化・再構成（システム手法の比較）

- **少なくて済む投影数** と **同じ投影数をより速く計算する** は区別。
- 連続OFFによる状態共有は[03_KV_CACHE](03_KV_CACHE.md)を参照。
- 速さはGPUの実効Critical-path時間、Batch、Context長、メモリ帯域に依存。
- **予測器の推論が追加されたせいで高速化を失う**なら採用しない。

## 8. 先行研究への帰属・新規性境界

- [vSkipper: arXiv:2609.37062](https://arxiv.org/abs/2609.37062)はスキップ層のKVを直ちに射影するProject-Onlyを含むServing方式。**Dynamic Skipと高速Serving自体は既知**。
- [AnchorKV: arXiv:2611.00117](https://arxiv.org/abs/2611.00117)、[Residual Stream: arXiv:2603.19664](https://arxiv.org/abs/2603.19664)はResidualからのKV再構成の先行研究。**再構成や容量判定自体は既知**。
- [AsymCache: arXiv:2606.02964](https://arxiv.org/abs/2606.02964)はKV Cacheの残存・再計算をGPU Kernel費用により最適化する先行研究。**費用認識Scheduler自体は既知**。
- [Dr.LLM: arXiv:2510.12773](https://arxiv.org/abs/2510.12773)は凍結モデルの経路探索・品質改善の先行研究。**動的経路自体は既知**。

**本研究の新規性候補：** *トークン単位の全中間層ON/OFFを学習することが、正確な過去KVの将来需要を内生的に変え、その実GPU費用・品質のトレードオフをRouterの方策へ帰還させること*。

**未検証・重要：** 上記の境界が未公開の同等手法に抵触しないことは保証できない。**本節の命題1〜3を新規の数学定理として主張しない**。研究成果の可能性は、組合せの有効性と妥当な対照実験によって判断する。
