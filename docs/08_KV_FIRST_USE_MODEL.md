# 08｜将来の初回KV需要・補完負債・経路学習の理論モデル

> **状態：未確定の研究設計案。** 実装・学習・GPU測定は行わない。第1・最終層の必須実行、全LLM重み凍結、第1層から単一Linear Routerで全中間層ON/OFFを出す骨格は**変更しない**。

## 1. 解きたい問題を一つに限定する

あるトークンが層 `j` をスキップしてKVを生成しなかったとき、次のトークンが直ちに同じ層を使うかもしれないし、生成が終わるまで使わないかもしれない。

この差は、単に「スキップしたトークン数」や「保存状態のバイト数」だけからは決まらない。重視すべきなのは、**当該層のKVが初めて必要になる時刻、補完時点の欠損数、GPUの同期・待機、保存期間、生成終了による不要化**である。

研究の中心候補は、**Layer Routerが引き起こす将来のKV補完要求を品質制約付きの総GPU費用で扱うこと**。

### 4つの独立な量

| 量 | 意味 | 誤認しないこと |
|---|---|---|
| **需要確率** | 現在のSkip後、生成終了までにその層が再度ONになる確率 | 需要確率だけでは補完時間が決まらない |
| **初回需要時刻** | 初めて当該層をONにするまでの距離 | 直ちにONと、長期Skip後のONは同じではない |
| **補完バースト** | ONになった瞬間に欠損している過去位置のKVと、その集約計算 | 単一トークンの射影時間を単純に掛け算できない |
| **保存負担** | 層入力（共有区間あり）を補完または安全な破棄まで保持する費用 | バイト数とGPU時間は単位が異なる |

## 3. 初回需要分布：独立性を仮定しない導出

位置tで層jをSkipしたあと、その層を次にONにする時刻を考える。

### 定義

```math
U_{j,t}=\inf\{u\ge 1:m_{t+u,j}=1\}
```

条件付き初回需要ハザードを、

```math
\alpha_{j,u}=
\mathbb P\!\left(U_{j,t}=u\mid U_{j,t}\ge u,\mathcal F_t,m_{t,j}=0\right)
```

とする。生成が終了して再利用されない場合は `U=∞` と扱う。

### 厳密な確率分解（帰納法）

初期に将来需要がまだ無いのは確実なので `S_{j,0}=1`。uまで需要が生じない確率は、

```math
S_{j,u}=
\mathbb P(U_{j,t}>u\mid\mathcal F_t,m_{t,j}=0)
=\prod_{v=1}^{u}(1-\alpha_{j,v})
```

である。

**証明：** u−1まで需要なしという事象 `U≥u` が成立している条件で、uでもONにならない確率は `1−α_{j,u}`。したがって `S_{j,u}=S_{j,u-1}(1−α_{j,u})`。初期条件を繰り返し代入すれば積の式が得られる。**異なる将来位置のマスク判断の独立性は必要ない**。

同様に、

```math
\mathbb P(U_{j,t}=u\mid\mathcal F_t,m_{t,j}=0)
=S_{j,u-1}\alpha_{j,u}
```

であるから、

```math
p_{j,H}=
\mathbb P(U_{j,t}\le H\mid\mathcal F_t,m_{t,j}=0)
=1-S_{j,H}
=\sum_{u=1}^{H}S_{j,u-1}\alpha_{j,u}
```

を得る。

**次元チェック：** `u,H`は無次元、各ハザード・生存確率も無次元。積と和は無次元の確率になり、整合する。

**ERROR CHECK：** この分解は条件付きハザードの定義から導かれる**確率の恒等式**であり、ハザードを実際に予測できる保証はない。生成トークン、Routerの未来の状態、EOSは互いに依存するため、`α`を単純な固定Bernoulli確率とみなすことはできない。未来の真のトークン・正解・経路を推論時に先取りしてはいけない。

### 仮想数値例

全uで初回ハザード0.1、H=10と**仮定だけ**した場合、

```math
p_{j,10}=1-(1-0.1)^{10}\simeq 0.6513
```

となる。**実際のLLMでの実測確率ではない**。

## 4. 「需要確率」だけではGPU費用が決まらない

同じ`p=0.5`であっても、次の2ケースは別のシステム費用を持ち得る。

- A：半分の生成で**次の1位置後に**層を使い、残りは終了まで使わない。
- B：半分の生成で**10位置後に**層を使い、残りは終了まで使わない。

どちらも少なくとも1回使う確率は0.5。ただし、BではそれまでのSkipにより欠損位置数や保存期間が大きくなりやすい。

### 初回需要での期待補完時間

```math
C^{\rm demand}_{j,t}(H)=
\sum_{u=1}^{H}S_{j,u-1}\alpha_{j,u}
\,\mathbb E\!\left[F_j(u,N_{j,u})\mid U_{j,t}=u,\mathcal F_t,m_{t,j}=0\right]
```

**導出：** 初回需要時刻uは相互排他的な事象。各時刻における「条件付き平均補完時間×その事象確率」を全時刻で足す全期待値の公式である。**各イベントで補完バーストを1回だけ数える**。

**次元チェック：** 確率×秒を有限個加算するため、`C^{demand}`の単位は秒となる。

**ERROR CHECK：** この式は**一層の初回補完バーストの期待追加時間**を表す近似モデルの構成であり、生成全体の実測Latencyや、現在トークンのマスク1ビットの限界費用と同じではない。Grouped GEMMや複数層の同時補完、CUDA Streamの重なりがあると、各層の値を単純加算して「全GPU時間」と主張できない。

### メモリは別の量

```math
A_{\rm hold}=\int_0^{T_{\rm decode}}M_{\rm pending}(r)\,{\rm d}r
```

物理的に共有している隠れ状態は**一度だけ**数える。容量時間積はメモリの使用期間を記述するための診断量であり、GPU計算時間とは加算できない。

**次元チェック：** B × s = B·s。単純なメモリ容量BともDecode時間sとも異なる。

**ERROR CHECK：** `A_hold`が小さくても、瞬間的ピークVRAMが容量を超えればOOM。メモリ上限は別途**ハード制約**とする。

## 5. 本来の目的は、全軌跡の実GPU時間を最小化すること

```math
\min_{\theta}\mathbb E_{\pi_\theta}[T_{\rm decode}]
\quad{\rm s.t.}\quad
\mathbb E_{\pi_\theta}[Q]\ge Q_0-\delta_Q,\quad
M_{\rm peak}\le M_{\rm budget}\ \text{(実行可能な全軌跡)}
```

- **品質下限：** 元モデルを下回らないという主張には、訓練用報酬とは独立した品質制約が必要。
- **GPU時間：** Router・Layer Executor・実際に発生したKV補完・待機・分岐を全て含む。
- **メモリ：** ピークVRAM上限を満たす。予算不足のときにマスクを無言で変えて正確性を犠牲にしない。

**重要：実際に支払った補完費用を総Decode時間に含めた上で、さらに同じ補完費用の予測値を罰則として足すと二重計上になる。**

予測値は**方策選択を補正する場合の候補情報**、または**実GPU時間がまだ測れない学習段階の代理費用**として扱う。最終目的に予測・実測を無条件に加算しない。

**次元チェック：** 目的はs。品質は無次元、メモリはB同士の比較であり、式全体に単位の混同はない。

### なぜこれで学術的に区別しやすくなるか

既存のキャッシュ再計算／保持手法は、与えられた生成需要に対して何を保存・再計算するかを最適化する。一方、本研究が検討するのは、**キャッシュ需要を生み出すトークン単位のLayer MaskをRouterが学習する**という点である。

ただし、これは独自性の**候補の説明**であり、既存手法に同等の共同最適化が存在しないと確認したわけではない。[出典台帳](PRIOR_ART_AND_ATTRIBUTION.md)で先行研究との重複を追跡する。

## 7. 論理的な反証可能性（実験は行わない）

| 設計仮説 | 破れ方・反例 |
|---|---|
| 将来利用確率が重要 | 該当層を二度と使わないなら、再構成費用は発生しない |
| 初回需要時刻が重要 | GPUが十分空いており全補完を完全に隠せるとき、時刻差がクリティカルパス遅延に反映されない場合がある |
| 負債状態をRouterに追加すべき | 第1層の特徴・履歴だけで将来必要量が十分に予測できるなら、状態補正は冗長 |
| すべての層でLazyが有利 | GQAにより入力保存の方が高コスト、または再構成の待機が長い場合に破れる |
| 二段階の共同最適化が有利 | Schedulerを後付けするだけで同じ最適経路を選べるなら追加利益はない |
| 個別層費用を足せば総費用になる | バッチ重み共有、Grouped GEMM、CUDA Streamの依存関係によって破れる |

## 8. 主要な先行研究との境界

- **vSkipper**：Layer Skip時もKVを直ちに書く`RUN/Project-Only`のServing設計。[arXiv:2609.37062](https://arxiv.org/abs/2609.37062)。本研究では、**その射影を遅延したときの追加的な利害**を扱う。
- **AnchorKV (residual anchors)**：残差からのKV再構成、保存と再計算の容量・時間のトレードオフ。[arXiv:2611.00117](https://arxiv.org/abs/2611.00117)。
- **AsymCache**：KV Cacheの再計算費用とGPU Attention Kernel効率を考慮するシステム。[arXiv:2606.02964](https://arxiv.org/abs/2606.02964)。
- **Dr.LLM**：凍結LLMの動的Layer Routingと経路学習。[arXiv:2510.12773](https://arxiv.org/abs/2510.12773)。

**既知要素を複合しただけで新規性を確定したと扱わない。** 参考にした設計と本研究側の仮説の対応は[出典台帳](PRIOR_ART_AND_ATTRIBUTION.md)に集約する。

## 9. 結論（設計段階）

1. 初回需要の**確率・時刻・欠損バースト**を区別する。
2. GPU費用は実効Latencyで扱い、層別予測値の足し算を厳密な総時間と誤認しない。
3. メモリは**ピーク容量のハード制約**を別に置く。
4. **学習はLinear Routerのみ。主候補はScheduler下の総Decode費用を使う学習（B）。**
5. 状態に依存する非学習補正（C）は、別の改善候補として採用可否を保留する。
6. 今は理論設計のみで、実装・GPU測定・学習実行の記録は作らない。
