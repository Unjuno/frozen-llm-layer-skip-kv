# 10｜新規性と合理性の監査：何を主張し、何を主張しないか

> **状態：研究上の差分の監査（未確定）。** 文献調査・実験・新規性証明は未完了。**主題は第1Attention活性の再利用＋単一Linear Headによる全中間層のトークン別実行領域学習**。遅延KV・GPU費用は、それを成立させる従属課題。実装・実験・期限は追加しない。

## 1. 「新規性を確保する」とは

先行研究で既知の技術を単に再命名しない。既知要素を明確に帰属しながら、**同じ品質制約の下で、既存方式にはない因果的な設計自由度と追加利益を示せるか**に研究を絞る。

| 区分 | 主張してよいこと／避けること | 根拠・状況 |
|---|---|---|
| **既知：凍結LLMへの軽量Router後付け** | 「Routerだけ学習」は発明と呼ばない | [Router-Tuning / Dr.LLM](PRIOR_ART_AND_ATTRIBUTION.md) |
| **既知：Dynamic Layer SkippingとGPU Serving** | 「SkipしてGPUで速くした」だけで新規性を主張しない | [vSkipper](PRIOR_ART_AND_ATTRIBUTION.md) |
| **既知：残差からの正確なKV再構成** | 「KVを遅延して作れる」だけで新規性を主張しない | [Residual Stream / AnchorKV](PRIOR_ART_AND_ATTRIBUTION.md) |
| **既知：再計算費用によるキャッシュ選択** | 「GPU費用を見てEager/Lazyを決める」だけを新規性としない | [AsymCache](PRIOR_ART_AND_ATTRIBUTION.md) |
| **一般的な数学的観察** | 最後のONより後のSkip位置はその要求内でKVを再利用しない、という[09の恒等式](09_LAST_USE_BOUND.md)を「新しい定理」と呼ばない | 条件付きの初等的な恒等式 |
| **未検証の独自性候補（主）** | **第1Attentionの既存活性を再利用し、単一Linear Headでトークン別の全中間層実行領域を一括学習する構成** | 類似研究との差分・追加利益を検証するまで新規性未確定 |
| **未検証の独自性候補（派生）** | **動的マスクが将来KV需要を生むことを考慮した追加学習** | 中心の学習設計が成立した後の補助研究 |

### 第1Attention活性の再利用は効率上の設計条件であり、独自性の主張ではない

[11 第1Attention活性とLinear Head](11_SHARED_ACTIVATION_ROUTING.md)で定義するように、通常のLLMが一度だけ計算した第1Attention活性をLinear Headでも参照する。これは**Router専用のAttentionモデルを増やさない合理的な構成**であって、それだけで新しいアルゴリズムとは呼ばない。

- 第1層Attentionは通常のDecodeとKV更新のために実行する。
- Headのために別のTransformerやAttentionを追加しない。
- **第1層のMLPは必ず完了**し、その出力を中間層へ渡す。
- Attention活性のTap位置（残差加算前後・Block完了後）は**未確定の設計詳細**として区別する。
- 第1Attentionを二重に計算しないのは**主設計の前提**。全層モデルはもともと第1Attentionを1回実行するため、これだけを元モデルに対する高速化とは言わない。Headの演算・分岐・同期には追加費用がある。

**新規性候補の優先順位：** 第1Attention活性に基づく**単一Linear Headの一括・トークン別実行領域選択を生成結果で学習する構造**をまず考察する。KV再構成費用を含む共同最適化は**追加の独自性候補**であり、主題を置き換えない。

## 2. 主題に対する新規性境界：活性再利用と動的実行領域の学習

**第一に確認するのは、共有した第1Attention活性から単一Linear Headが全中間層のトークン別ON/OFFを学ぶ構造を、既知のRouter-Tuning・Dr.LLM・FlexiDepth等とどう区別するかである。** 再利用するAttention活性そのものは既知の共有表現であり、無条件に新規性を主張しない。その後の派生課題として、**既知のキャッシュSchedulerに与えられるKV需要**と、**Layer Routerが自らKV需要を生み出す**問題を区別する。

- 既知のKV管理は、生成が必要とするキャッシュを保持・復元する費用を扱う。
- 本研究のRouterは、各トークンである層をON/OFFにすることで、**将来のKV需要の発生時刻と必要個数自体を変える**。
- 未来のONを完全に予測することはできず、**未来トークンや未来マスクを推論時に参照してはいけない**。
- そこで、**完了した生成軌跡の実効GPU費用**と品質を主学習信号とし、必要なら過去のKV負債に対する**非学習の状態補正**を考える。

**研究主張の候補（未確定）：**

> A frozen LLM reuses its existing first-layer attention activations as inputs to a single linear decision head that jointly selects all intermediate execution masks per generated token. Only this head is trained from complete generation trajectories; exact deferred KV reconstruction supports these dynamic execution paths. Cache-aware cost optimization is an optional subsequent extension.

**留保：** この記述だけでは新規性を保証できない。似た共同最適化が先行研究にないか、同等のBaselineが作れるかを文献調査と実験で検証する必要がある。

## 3. 必ず分けるべき二つの高速化メカニズム

| メカニズム | 何を削減するか | 関連する設計制約 | 誤った解釈 |
|---|---|---|---|
| **Projection elimination** | 需要が最後まで生じないSkip位置のKV射影 | 層ごとの**最終ON位置**、終了・再開条件 | SkipしたすべてのK/Vが不要になるわけではない |
| **Projection scheduling** | 射影個数を変えずに、Grouped GEMM/一括処理/非同期化で実GPU実効時間を削減 | 未補完容量・補完期限・Stream待機 | KV射影回数が減ったと誤認する |

[09_LAST_USE_BOUND.md](09_LAST_USE_BOUND.md)の厳密なマスク恒等式と、[08_KV_FIRST_USE_MODEL.md](08_KV_FIRST_USE_MODEL.md)の条件付き初回需要モデルを**別の正本**として扱う。

**重要：** vSkipperがスキップ時にProject-Onlyを実行することは、今回のEagerを強いBaselineにする理由である。一方、AsymCacheのKV eviction後の**Prefix再計算**は、保存層入力から行う**直接K/V射影**とは計算上の依存関係と費用形状が異なる。AsymCacheの位置依存コストを直接転用してはいけない。

## 4. 学習上の合理性：最小の学習可能モデルから変更しない

| 方策 | 何を改善するか | 学習可能パラメータ |
|---|---|---|
| **A：既存Linear Router** | 全マスクを生成報酬で学習するBaseline | Linear W,bのみ |
| **B：負債を含む費用で再学習** | 生成後の品質・**実際に支払ったGPU費用**を学習へ反映 | Linear W,bのみ |
| **C：任意の非学習KV状態補正** | 第1層特徴が同じでも補完状態が異なる場合の経路選択を区別 | Linear W,bのみ |
| **D：固定マスクへの退化を監査** | どの入力でも同じ層をSkipするならRouterの適応性が失われる | 新しい学習パラメータなし |

**Aを主たる研究対象**とする。Bは生成学習したAに対するKV/GPU費用の派生的拡張、Cは未確定の任意補正、Dは固定Skipへの退化の監査である。

[09](09_LAST_USE_BOUND.md)が示す「同じ平均ON率でも末尾OFF区間長が変わる」という結果は**事後の費用を解析するための性質**であり、時間的相関や末尾OFF長を**最大化する学習目的にしない**。連続して同じマスクが最適な場面は許すが、**連続させること自体を報酬にしない**。

### 撤回：前回マスクを維持させる補正は主方式から除外

以前の案では、前トークンのON/OFFを維持する加算バイアスを提案していた。しかし、**同じ層を継続的にSkipさせることそのものを学習するのは研究の主旨に反する**ため、これを研究方策の候補から撤回する。

| Routerが出すマスクの振る舞い | 解釈 | 本研究での扱い |
|---|---|---|
| **すべてのプロンプト・全トークンで同じマスク** | 実質的に静的Layer Pruning。Routerの適応性は説明できない | 強い固定経路Baseline |
| **プロンプトごとに異なるが同一プロンプト内では一定** | Prompt条件付きの経路選択 | 比較・診断用の部分的な適応 |
| **トークンの内容と生成履歴に応じてマスクが変わる** | 狙っているToken-wise Dynamic Routing | **主研究方式** |

ただし、**毎トークン必ずマスクを変えなければならないわけではない**。入力・文脈に適応した結果、連続した数トークンで同じマスクが最適になることもある。逆に、マスクを強制的にランダム化・多様化する目的関数も不合理である。

- **「同一マスクを保つほど高報酬」という項は採用しない。**
- GPU実行時間・保存KV負債・品質は**実際の生成経路に付随する費用・性能としてのみ評価**する。
- 時間的相関、マスク変動回数、末尾OFF長は**診断指標**であり、直接の最適化目標ではない。
- 必要ならKV準備状況による非学習の費用補正（C）を検討するが、**固定マスク化を促進していないかを別途確認**する。
- 学習済み方策が、同等の総GPU費用の**最良の固定Skip経路**を超えないなら、Token-wise Routerの有効性を主張しない。最良固定経路は未知データの正解を参照せず、開発データだけで選定する。

**訂正理由：** 「末尾のOFFが長いとKV射影を省き得る」という数学的事実は、「長くOFFを維持するべき」という最適化原則を意味しない。後者は品質・GPUバッチ処理・ONへの復帰時の再構成費用を無視するため、誤った目標設定である。

### なぜ追加の報酬を安易に足さないのか

- **主目的**はタスク品質と生成の総GPU実効時間。KV補完はその時間の一部。
- 「本来のGPU実測時間」に「予測補完費用」をもう一度足すと、**同じ費用の二重計上**になる。
- `A_j`（末尾OFF区間の長さ）は**解析指標**として有用だが、これを直接最大化すると品質・メモリを犠牲にする可能性がある。
- 予測補完費用は、**測定していない費用の代理**、または**実行直前の非学習スコア補正**としてのみ候補にする。
- 報酬を追加するなら、どの**既存の目的には含まれていない**費用を表しているかを先に明示する。

## 5. 最も厳しい反証と、失敗した場合に意味すること

| 疑うべき点 | 失敗シナリオ | 研究上の解釈 |
|---|---|---|
| **遅延KVは本当に計算を減らすか** | 層が最後まで断続的にONとなり、ほぼ全Skip位置のKVを結局再構成 | Layer Skip自体は有効でもLazyの「射影数削減」は限定的。**一括化による利益**を別に考える |
| **費用認識の学習が必要か** | Eager下で学習しSchedulerを後付けしただけで同じ品質・GPU時間になる | 追加の共同学習は有用でなかったと判断。新規性の中心を再検討 |
| **負債状態を明示入力すべきか** | 状態補正による追加利益がない、または補正器の費用が上回る | Bで十分。Cを不採用にする |
| **Routerが静的マスクへ退化していないか** | 異なる入力でも同じ層群をOFFにし、最良固定Skipとの差がない | マスク持続報酬を撤回し、固定経路Baselineと比較する |
| **線形方策の表現力は足りるか** | 同じ第1層特徴から最適マスクを区別できない | 学習不足だけではなく、入力情報の不足・方策族の制約と結論付ける |
| **リアルGPUで速くなるか** | 重み帯域・Batch・同期の費用が計算省略を超える | FLOPsのみの成果は速度の主張にならない |

## 7. 今回の提案の結論

**より合理的な主戦略：**

1. **既存第1Attention活性の共有→単一Linear Head→中間層全体のトークン別マスク**という主構造を保つ。
2. **Headだけを実際の生成報酬で学習し、同等の費用で固定Skipより適応的選択が有利か**を主たる理論・将来の検証課題にする。
3. SkipによるKV欠損は正しく補完し、**第1Attention・第1層MLP・最終層の実行を省略しない**。
4. KV費用・最後のON位置・GPU補完バーストは**副次的な費用解析**として扱い、同じマスクを維持する学習目標を作らない。
5. KV補完費用込みの再学習が後付けSchedulerに勝つ場合だけ、**共同最適化の追加的な効果**として主張する。

**この結論は設計上の優先順位であり、未測定の性能改善ではない。**
