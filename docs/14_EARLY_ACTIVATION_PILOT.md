# 14｜初段Attention活性による実行領域選択：新規性Pilot（2026-11-26）

## 次の実験（実施条件）

- Nativeで正解が得られる問題・十分な生成長を先に確定する。正解評価器と書式条件を固定し、文字列類似度だけで誤答を学習成功としない。
- 学習・開発・最終評価の独立集合を確保。複数固定マスクを開発集合だけで探索して選択し、同一の計算予算で動的選択と比較する。
- 同一予算診断ではEmbedding／Attention活性／第1Block出力／固定・ランダム選択を比較し、候補集合・正則化・閾値を最終評価前に固定する。事後最良固定とOracleの差も報告し、動的選択自体に価値があるかを診断する。
- 生成学習は26-bit単一Linear Headのみという主構造を保持。複数seed、探索と決定的評価の実行率差、マスク退化、実GPU時間とVRAMを別途評価。

**H/T/D/C/U：** H=初段Attention共有が同予算で固定選択より低NLL／高品質を達成する。T=今回は小規模CPU・1 seedの探索的試験。D=動的優位は未実証、**UNCERTAIN**。C=固定経路で十分、初段特徴の不足、探索と評価分布の差、報酬の不良、生成長、少数標本。U=標本数・候補集合・書式・精度・seed、GPU未使用。数値は実測、解釈は暫定。学術的新規性は未確定。

## Pilot C: 60問・12固定候補・独立調整による再検証

**事前設定は実行前のCommit 4c1cce01f2671027060ba422dba401fdd923b05cに固定。** Qwen3-0.6B、同一revision、PyTorch 2.8.0+cpu / Transformers 4.57.3 / Python 3.12.3、Linux aarch64、CPU 2スレッド、FP32、Batch12、eager Attention。新規の合成4択60問（加算・数値比較・文脈内検索）、学習24／調整12／最終評価24。12候補すべて24/28ブロックを実行。末端1ステップだけを比較し、Skipした末端位置のKVは将来利用しないので生成しない。PrefillのCacheを各経路で共通使用・復元。これは**連続DecodeのKV整合性・速度を再検証する実験ではない**。

**判定：NOT_DEMONSTRATED / UNCERTAIN。** タスク成立性が未達であり、動的選択の優位性を立証していない。新規性を確保できたとは主張しない。主構造（第1Attention活性再利用・26-bit Linear Head・生成報酬学習・凍結LLM・正確な遅延KV）は変更しない。今回の12候補選択は本来の26-bit生成学習を置換するものではない。Glavas et al. ## Pilot D: 同一プロンプト内の必要層の変化と早期活性の予測能力

[実験コード](../experiments/qwen3/probe_within_prompt.py) ／ [全144位置の実測・選択結果](../results/qwen3_within_prompt_cpu_2026-11-26.json)

**結果：NOT_DEMONSTRATED。** ただし、同一プロンプト内でトークンごとに経路を変える価値が、この候補集合・元分布保存という評価条件下に存在することは確認した。初段Attentionの入力固有の追加利益は未実証。

### 事前固定した設計

実行前Commit `070bce525e93bb786339b9270c9a038e3db43006`。事前学習済みQwen3-0.6B、Revision `c1899de289a04d12100db370d81485cdf75e47ca`、PyTorch 2.8.0+cpu、Transformers 4.57.3、Python 3.12.3、Linux aarch64、FP32、CPU 2スレッド、Batch 24、eager Attention、Seed 2026112603。データは新規24プロンプト（説明、算術、文脈検索、列挙）、学習8／調整4／最終評価12。元モデルでgreedy生成し、各プロンプトの6 Decode位置を調べる。全144位置を収集、最終評価72位置、終了コード0。各経路候補は4中間層をSkipし24/28層を実行。8候補はPilot Cの12候補から事前選定（前回の有力固定候補と後段連続Skip候補を含む）であり、全26-bit空間を網羅しない。

比較対象は各位置の**元モデル自身の全語彙出力分布**。候補の分布へのKL（元→候補、nat/位置）を主指標とし、元のargmaxトークン一致率を補助指標とする。プロンプトを等重みで集計。正解ラベルや元モデルの正解率を使用しないため、回答書式の問題を避けられるが、品質改善やタスク成立性を検証し直したものではない。

毎位置、Native生成履歴を共通にし、その位置だけ各候補マスクを試す。Skip位置のK/Vは後続で使わないので生成せず、候補のCacheをcropした後に保存したNativeのKV末尾を復元する。初回・最終位置の全ON再実行でLogits最大絶対差0、各層のCache末尾と長さも検査した。**これは実際の動的方策による連続生成・KV復元速度の検証ではない**。本来の26ビット生成学習の代替ではなく、8候補の損失を線形読み出しする補助診断。学習特徴の中心化・スケーリングは学習集合だけで決定し、正則化係数は調整集合だけで選ぶ。固定マスクも学習＋調整集合の候補比較で選ぶ。プロンプト単位の線形対照は最初のDecode活性のみを読み、以降は同一経路を使う。事後Oracleは最終評価の損失を使う診断で実用不可。

### 重要な反証と判断

- トークン単位Oracleがプロンプト単位Oracleを上回ることから、限定された経路候補でも位置ごとの改善余地がある。ただし大きな正解率差や最速経路の証明ではない。
- 実際の残差後線形選択は12評価プロンプト中2つのみで複数マスクを選んだ。10プロンプトで単一経路。しかも**Embedding線形とAttention出力線形・残差後線形は全72位置で同じマスク選択**。初段Attentionの文脈情報による追加利益は立証できなかった。
- プロンプト単位の残差後線形対照は今回のトークン別線形よりKLもargmax一致も良い。学習・調整の標本不足、候補集合の制約、ridge回帰による平均化、目標と実際の26-bit生成学習の相違があり、初段Attention方式の一般的不可能性は主張できない。
- GPU速度・実行時間の優位性は測っていない。KL保存はタスク品質改善の代替指標ではない。主構造は変更しない。

**H/T/D/C/U:** H=残差後線形が固定とプロンプト単位線形より0.02 nat/位置以上良く、対応付きbootstrap下限が正、さらに同一プロンプト内のマスク置換対照にも勝つ。T=事前固定した24プロンプト×6位置、8候補。D=全144位置収集PASS、主要な改善条件FAIL（有効性未実証）。C=静的/プロンプト適応で十分、線形読み出しの学習不足、Embeddingで説明可能、初段特徴の不足。U=12独立評価プロンプト、CPU FP32、候補集合、元生成を固定した一段反実仮想、単一設定。標本内bootstrap区間であり広範な分布への保証ではない。

**次の最小検証:** まず元モデルの生成品質が成立する独立課題を選ぶ。次に学習データを増やし、同じ入力・候補・予算のEmbedding対照と初段Attention対照を比較し、前者からの追加利益を測る。その後に本来の26-bitオンポリシー学習で検証する。マスク変更を報酬で強制しない。
